Runtime setup运行配置

Configure Codex explicitly.显式配置 Codex。

MAARS should not depend on a hidden global profile. Set model, reasoning effort, sandbox provider, timeout, and proxy behavior in .env.MAARS 不应依赖隐藏的全局 profile。模型、推理强度、沙箱提供器、超时和代理行为都应在 .env 中显式设置。

Minimum config最小配置

For a real local run, start with these values. Codex must already be authenticated on the machine.真实本地运行可以从这些值开始。Codex 需要已经在机器上完成认证。

MAARS_OPENAI_API_KEY=...
MAARS_OPENAI_MODEL=gpt-5.5
MAARS_RESEARCH_MAX_ITERATIONS=3
MAARS_TEAM_MAX_DELEGATIONS=5
MAARS_DATASET_DIR=data/

MAARS_CODEX_BIN=codex
MAARS_CODEX_MODEL=gpt-5.5
MAARS_CODEX_REASONING_EFFORT=high
MAARS_CODEX_VERBOSITY=low
MAARS_CODEX_SANDBOX=workspace-write
MAARS_CODEX_INHERIT_PROXY=true
MAARS_CODEX_SANDBOX_PROVIDER=local
MAARS_CODEX_TIMEOUT=4200

Reasoning effort推理强度

MAARS_CODEX_REASONING_EFFORT is passed to Codex as model_reasoning_effort. Use it to tune cost, latency, and reliability.MAARS_CODEX_REASONING_EFFORT 会作为 model_reasoning_effort 传给 Codex，可用于平衡成本、延迟与可靠性。

Value值Use case适用场景
lowFast smoke tests and simple file-producing tasks.快速 smoke test 与简单产文件任务。
mediumRoutine analysis where failures are cheap.失败成本较低的常规分析。
highDefault for research execution.研究执行的默认建议值。
xhighHard tasks, brittle experiments, or final production runs.困难任务、脆弱实验或最终生产运行。

Sandbox providers沙箱提供器

Local provider runs codex exec directly in a task workspace. Docker provider wraps the same command in docker run.本地提供器直接在任务工作区运行 codex exec。Docker 提供器用 docker run 包装同一条命令。

# Local, recommended first
MAARS_CODEX_SANDBOX_PROVIDER=local

# Docker, optional
MAARS_CODEX_SANDBOX_PROVIDER=docker
MAARS_CODEX_DOCKER_IMAGE=maars-codex:latest
MAARS_CODEX_DOCKER_BIN=docker
MAARS_CODEX_DOCKER_CODEX_BIN=codex
MAARS_CODEX_DOCKER_GPUS=all

The Docker image must include Codex CLI and expected experiment dependencies. MAARS does not restore the old code_execute tool path.Docker 镜像必须包含 Codex CLI 与预期实验依赖。MAARS 不恢复旧的 code_execute 工具路径。

Proxy inheritance代理继承

Codex task execution inherits global proxy variables by default. Keep MAARS_CODEX_INHERIT_PROXY=true when the runtime depends on a local or corporate proxy.Codex 任务执行默认继承全局代理变量。当运行时依赖本地或公司代理时，保持 MAARS_CODEX_INHERIT_PROXY=true。

Skills are part of the roadmapSkills 是路线的一部分

MAARS should work with the normal Codex skill ecosystem. If a skill breaks startup, fix the skill rather than hiding all skills from the runtime.MAARS 应该与正常的 Codex skill 生态协同。如果某个 skill 破坏启动，应修复 skill，而不是把所有 skill 从运行时隐藏。

Smoke test

Before a full run, verify that Codex can execute one schema-constrained task through MAARS's executor.完整运行前，先确认 Codex 能通过 MAARS 执行器完成一个受 schema 约束的任务。

MAARS_OPENAI_API_KEY=test \
MAARS_OPENAI_MODEL=gpt-test \
MAARS_RESEARCH_MAX_ITERATIONS=1 \
MAARS_TEAM_MAX_DELEGATIONS=1 \
MAARS_KAGGLE_API_TOKEN= \
MAARS_DATASET_DIR=data \
MAARS_API_CONCURRENCY=1 \
MAARS_OUTPUT_LANGUAGE=Chinese \
.venv/bin/python -m pytest tests/test_codex_executor.py -q
A full MAARS run needs OpenAI configuration for prose stages and Codex configuration for Research task execution.完整 MAARS 运行需要为文本阶段配置 OpenAI，也需要为 Research 任务执行配置 Codex。
Runtime setup is explicit so Codex behavior is reproducible.运行时配置保持显式，Codex 行为才可复现。
