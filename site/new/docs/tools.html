Runtime setup

Configure Codex explicitly.

MAARS should not depend on a hidden global Codex profile. Set the model, reasoning effort, sandbox provider, and timeout in .env so runs are reproducible.

Minimum config

For a real local run, start with these values. Codex must already be authenticated on the machine, and MAARS_OPENAI_API_KEY should be available for non-executor stages.

MAARS_OPENAI_API_KEY=...
MAARS_OPENAI_MODEL=gpt-5.5
MAARS_RESEARCH_MAX_ITERATIONS=3
MAARS_TEAM_MAX_DELEGATIONS=5
MAARS_DATASET_DIR=data/

MAARS_CODEX_BIN=codex
MAARS_CODEX_MODEL=gpt-5.5
MAARS_CODEX_REASONING_EFFORT=high
MAARS_CODEX_VERBOSITY=low
MAARS_CODEX_SANDBOX=workspace-write
MAARS_CODEX_INHERIT_PROXY=true
MAARS_CODEX_SANDBOX_PROVIDER=local
MAARS_CODEX_TIMEOUT=4200

Reasoning effort

MAARS_CODEX_REASONING_EFFORT is passed to Codex as model_reasoning_effort. Use it to tune cost, latency, and task reliability.

ValueUse case
lowFast smoke tests and simple file-producing tasks.
mediumRoutine analysis where failures are cheap.
highDefault for research execution. Better planning and debugging without max cost.
xhighHard tasks, brittle experiments, or final production runs.

Sandbox providers

Local provider runs codex exec directly in a task workspace. Docker provider wraps the same command in docker run and mounts the workspace into the container.

# Local, recommended first
MAARS_CODEX_SANDBOX_PROVIDER=local

# Docker, optional
MAARS_CODEX_SANDBOX_PROVIDER=docker
MAARS_CODEX_DOCKER_IMAGE=maars-codex:latest
MAARS_CODEX_DOCKER_BIN=docker
MAARS_CODEX_DOCKER_CODEX_BIN=codex
MAARS_CODEX_DOCKER_GPUS=all

The Docker image must include Codex CLI and the experiment dependencies you expect tasks to use. MAARS does not restore the old code_execute tool path.

For serious experiment runs, prefer a clean GPU host or image with CUDA, Python dependencies, Codex CLI, and authenticated Codex access already prepared.

Proxy inheritance

Codex task execution inherits global proxy variables by default: HTTP_PROXY, HTTPS_PROXY, ALL_PROXY, NO_PROXY, and lowercase variants. Keep MAARS_CODEX_INHERIT_PROXY=true when the runtime depends on a local or corporate proxy.

Skills are part of the roadmap

MAARS should work with the normal Codex skill ecosystem. If a skill breaks Codex startup, fix the skill rather than hiding all skills from the runtime. Durable lessons from failed runs can become maintained skills, but execution contracts should stay explicit in MAARS code and prompts.

Smoke test

Before a full pipeline run, verify that Codex can execute one schema-constrained task through MAARS's executor.

MAARS_OPENAI_API_KEY=test \
MAARS_OPENAI_MODEL=gpt-test \
MAARS_RESEARCH_MAX_ITERATIONS=1 \
MAARS_TEAM_MAX_DELEGATIONS=1 \
MAARS_KAGGLE_API_TOKEN= \
MAARS_DATASET_DIR=data \
MAARS_API_CONCURRENCY=1 \
MAARS_OUTPUT_LANGUAGE=Chinese \
.venv/bin/python -m pytest tests/test_codex_executor.py -q

For an end-to-end executor smoke test, run a small CodexExecutor task that writes one artifact and returns JSON. This bypasses Refine and Write and only exercises Codex task execution.

Full run

After the smoke test, start the app and run a small research idea first. Keep the first task analysis-only or file-producing so failures are easy to inspect.

bash start.sh

# Open http://localhost:8000
# Paste a concise research idea or a path such as showcase/example_idea.md
A full MAARS run needs OpenAI configuration for Refine/Strategy/Write and Codex configuration for Research task execution.
Runtime setup is intentionally explicit so Codex behavior is reproducible.
