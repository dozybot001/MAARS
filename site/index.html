Architecture boundaries架构边界

MAARS is easier to reason about when every layer has one job. The runtime controls flow. Codex does execution. The session store is the source of truth.当每一层只做一件事时，MAARS 更容易维护：运行时控制流程，Codex 执行任务，session 存储保存事实。

Frontend and API前端与 API

FastAPI routes, SSE events, and static UI show stage and task progress.FastAPI 路由、SSE 事件和静态 UI 展示阶段与任务进度。

02

Pipeline管线

Refine, Research, Write, and Polish remain explicit persisted stages.Refine、Research、Write、Polish 仍是可持久化的显式阶段。

03

LangGraph

Research rounds and task retries are state graphs instead of hand-written loops.研究轮次与任务重试由状态图承载，而不是手写循环堆叠。

04

Codex ExecutorCodex 执行器

Each atomic task becomes one non-interactive Codex session with structured JSON output.每个原子任务对应一次非交互式 Codex 会话，并返回结构化 JSON。

05

Artifacts产物

Outputs move through workspaces, artifact folders, summaries, and final paper inputs.输出经过工作区、产物目录、摘要，最终进入论文写作输入。

Runtime model运行时模型

The old Docker execution tool path is retired. Docker remains useful, but only as an optional sandbox provider underneath Codex.旧的 Docker 执行工具路径已退役。Docker 仍然有价值，但只作为 Codex 下方的可选沙箱提供器。

Runtime

Python decides control flowPython 决定控制流

Routing, iteration stopping, task scheduling, retries, and verification stay deterministic.路由、迭代停止、任务调度、重试与验证都保留在确定性的应用逻辑里。

Executor

Codex performs workCodex 执行工作

Codex receives one task, runs commands, writes files, and returns schema-constrained output.Codex 接收单个任务、运行命令、写入文件，并返回受 schema 约束的输出。

Sandbox

Provider is pluggable沙箱可插拔

Local mode is default. Docker mode wraps the same Codex command in a configured image.默认使用本地模式；Docker 模式只是在配置好的镜像里包装同一条 Codex 命令。

Configuration for a real run真实运行配置

Start with local Codex. Switch to Docker only when a pinned image, stronger isolation, or GPU pass-through is needed.优先从本地 Codex 开始。只有在需要固定镜像、更强隔离或 GPU 透传时，再切到 Docker。

Local Codex provider本地 Codex 提供器

MAARS_OPENAI_API_KEY=...
MAARS_OPENAI_MODEL=gpt-5.5
MAARS_CODEX_BIN=codex
MAARS_CODEX_MODEL=gpt-5.5
MAARS_CODEX_REASONING_EFFORT=high
MAARS_CODEX_SANDBOX=workspace-write
MAARS_CODEX_SANDBOX_PROVIDER=local

Best default for development. Codex uses normal local auth and MAARS creates one workspace per task.这是开发时最合适的默认值。Codex 使用本机认证，MAARS 为每个任务创建独立工作区。

Docker Codex providerDocker Codex 提供器

MAARS_CODEX_SANDBOX_PROVIDER=docker
MAARS_CODEX_DOCKER_IMAGE=maars-codex:latest
MAARS_CODEX_DOCKER_BIN=docker
MAARS_CODEX_DOCKER_CODEX_BIN=codex
MAARS_CODEX_DOCKER_GPUS=all

The image must contain Codex CLI and experiment dependencies. GPU hosts can pass devices through explicitly.镜像必须包含 Codex CLI 与实验依赖。有 GPU 的环境可以显式透传设备。
